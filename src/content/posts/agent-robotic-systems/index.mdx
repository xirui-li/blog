## How the Loop Used to Be

{/* A short review, no subsections. Four paragraphs and one figure.

    1. The same loop, instantiated end to end: one network takes over the whole agent side — observations in, actions out, at a fixed rate.

    2. π0.5 [1], described through the loop: o = images + language instruction + proprioception; π first predicts a high-level subtask in language, then an action expert outputs low-level actions; a = action chunks at a fixed rate; generalization comes from co-training on heterogeneous data.

    3. MolmoAct 2 [2], focusing on how it differs: it reasons before acting (spatial / embodied reasoning on the Molmo2-ER backbone), and MolmoAct2-Think adapts how deeply it reasons. Part of the thinking becomes explicit, but it still happens inside one forward pass.

    4. What both share, and what the loop is missing (sets up the next three sections):
       - one step is still one control tick, not "one action with an outcome";
       - memory is little more than the latest frames;
       - there is no explicit channel for what an action achieved — failure shows up only indirectly in the next image;
       - improving means retraining.

    Figure idea: the "collapsed" loop — Figure 1's layout with Memory and Policy merged into one "π0.5 / MolmoAct 2" box, Learning greyed out as offline training, and the action edge labeled "fixed-rate action chunks". */}

## What Flows Through the Loop

{/* Representation. For each, contrast end-to-end ↔ agent:
    - Observation space — the o_{t+1} edge; perception/grounding in Z (or as a tool the agent calls).
    - Memory & belief — the memory node; world representation; "record executed actions" edge.
    - Context construction — the b_t edge: what part of memory reaches the policy.
    - Action space — the a_t edge: joint commands → action chunks → skill calls.
    - Skill design — interface (name, args, description), granularity, pre/postconditions, what a skill returns (its result is an observation), learned policies as skills. */}

## When It Flows

{/* Time structure of the loop (not a single place on the diagram):
    - Commitment horizon: single step → action chunking → skills (a skill is a nested inner loop inside a_t).
    - Sync vs async: does the policy wait while a_t executes, or keep running? (chunked async inference ↔ agents monitoring background skills)
    - Interruption & recovery: issuing a new a_t before the last one finishes.
    Figure idea: 2×3 table — horizon (step / chunk / skill) × sync / async. */}

## How the Loop Improves

{/* Two learning paths on the diagram:
    - Weights: learning module + "interaction experience" / "improve policy" edges (RL, fine-tuning).
    - Context: in-context learning — experience → memory → b_t → policy, no weight update (demos, past episodes, reflections; in-context imitation on the policy side).
    - Structure: growing or rewriting the skill library.
    Also feedback: who decides success (R, r_{t+1}). */}
