## Task: Instruction and Prior Knowledge

{/* Figure 1: the Task box (g, K) — set once per episode.

    Instruction g — how prior work has specified the task:
    - Language: the default for VLAs (π0.5, MolmoAct 2) and for VLM agents, where g is simply a text prompt.
    - Goal images: show the desired end state (multimodal goal-conditioned policies, e.g. GR-MG, https://arxiv.org/abs/2408.14368).
    - Sketches and trajectories: RT-Trajectory conditions on rough 2D motion sketches (ICLR 2024, https://arxiv.org/abs/2311.01977); RT-Sketch on hand-drawn goal sketches (CoRL 2024, https://arxiv.org/abs/2403.02709).
    - Videos and demonstrations: learn the task from a demo video, including from humans with a different body (Vid2Robot, https://arxiv.org/abs/2403.12943).
    - Multimodal prompts: VIMA interleaves text and images in one prompt (ICML 2023, https://proceedings.mlr.press/v202/jiang23b.html); MUTEX accepts six modalities — video, goal image, text, speech (https://arxiv.org/abs/2309.14320).
    - Survey framing: language, goal images, human videos, rewards, trajectory scratches, sketches (https://arxiv.org/abs/2312.08782).
    - Trade-off to discuss: language is easy but ambiguous; images are precise but over-specified; sketches sit in between (RT-Sketch's argument).
    - End-to-end vs agent: an end-to-end model fixes g's modality at training time; a VLM agent mostly receives text, but can take images or video in context — which leads into K.

    Prior knowledge K — and in-context learning:
    - What goes in K: skill descriptions, API docs, rules, maps — and examples / demonstrations.
    - In-context learning (ICL): the agent adapts to a task from examples placed in its context at deployment, with no gradient update. GPT-Policy [4] does this with a VLM agent: demonstrations (even human videos without robot action labels), examples, and interaction feedback go into the context; a context compiler condenses them; a constrained controller verifies and executes each proposed action and reports the outcome.
    - On the loop: demonstrations enter as K (seeding M), feedback arrives as observations and is written into M, and the compiler is context construction (the mₜ edge). No weights change — so ICL lives in Task + Memory, not in the Learning box.
    - End-to-end: K is baked into the weights; adapting means retraining. Agent: K is explicit and can be read, edited, swapped, or extended with new examples. */}

## Interface: Observation and Action Spaces

{/* Figure 1: the two edges between agent and environment — the only way they interact.
    Observation space (o_{t+1}, r_{t+1}):
    - raw pixels and proprioception vs. structured perception (objects, poses) vs. skill return values ("grasp failed, cup on table");
    - active perception: "look" as an action (e.g. detect("cup")) instead of passively receiving every frame;
    - is the reward r visible at run time? Usually not — mostly for training and evaluation.
    Action space (a_t): low-level commands → skill calls → programs (code as policy).
    - What separates them: what an action means, whether it returns a result, and who decides when it ends.
    - Action chunking does NOT change the action space (still low-level commands, just k at a time) — see "Time".
    Skill design (the agent-side form of the action space):
    - interface: name, arguments, description for the model, pre/postconditions;
    - a skill's return value is an observation — this closes the loop with the observation space;
    - an end-to-end policy (VLA) can itself be one skill. */}

## Inside the Agent: Memory and Policy

{/* Figure 1: the agent box — Memory M and Policy π, joined by m_t / b_t and executed a_t.
    Memory M (internal state, not an input; outline from the four questions):
    - representation & capacity: raw history, summaries, world state, or a belief distribution?
    - writing & forgetting: what gets written (observations, executed actions, g, K), when it is compressed or dropped;
    - reading: what part of M reaches the policy each step (context construction — the m_t / b_t edge);
    - persistence: within one episode, or across tasks?
    - End-to-end: m_t ≈ the latest few frames. Agent: explicit execution record, world state, possibly long-term memory.
    Policy π:
    - end-to-end: one forward pass from observation to action; any reasoning stays inside the network;
    - agent: ReAct-style — reason about m_t, choose an action, read its result, reason again. */}

## Time: Steps, Chunks, and Asynchrony

{/* Figure 1: "t = 0, 1, 2, …" — the time structure of the agent–environment loop.
    - Commitment horizon: how long one decision is executed before looking again — single step → action chunk → skill (a skill is a nested inner loop inside a_t).
    - Sync vs async: does the policy wait while a_t executes, or keep running? (async chunked inference ↔ agents monitoring background skills)
    - Interruption & recovery: issuing a new a_t before the last one finishes.
    - Figure idea: horizon (step / chunk / skill) × sync / async, as a 2D grid.
      e.g. a chunked VLA = low-level action space + medium horizon; a synchronous agent = skill action space + long, variable horizon. */}

## Learning Across Episodes

{/* Figure 1: the Learning box and the stack of N episodes — outside the runtime loop.
    - Meta-learning, continual learning, recursive self-improvement (RSI): spell out RSI on first use.
    - What changes: the policy π and memory M (how M is updated; sometimes long-term memory directly) — not one step of the runtime.
    - In-context learning is NOT in this box: weights stay fixed and only the context changes (e.g. GPT-Policy [4]) — it is covered under Task (K) and Inside the Agent (M).
    - Feedback for learning: who decides success (R, r_{t+1}) — rules, learned detectors, or a VLM. */}

## End-to-End vs. Agent Systems

{/* Framing: the three are not on the same layer. A VLM-driven agent orchestrates (what to do, which capability to call); a VLA is an action model (how to move next); a WAM couples action with prediction (what happens if I act). Comparing "VLM agent vs VLA/WAM" often compares a whole orchestration system with one of its action models — so this is not a ranking. A VLA can use a VLM backbone, and an agent can call a VLA as one of its skills.

    Background on the end-to-end families (inputs and outputs):
    - VLA, π0.5 [1] / MolmoAct 2 [2]: images + instruction (+ proprioception) → fixed-rate action chunks. π0.5 predicts a subtask in language first; MolmoAct 2 reasons spatially before acting. Reasoning stays inside one forward pass.
    - WAM, DreamZero [3] (named the family): same input → future video + the actions that produce it, from a video-diffusion backbone running closed loop. Reported to generalize to unseen environments and objects better than strong pretrained VLAs in its setting — one setting, not a general ranking.

    Where an agent's advantage comes from (analysis, not a proven rule):
    1. Transferable knowledge — web-scale vision-language data vs scarce, embodiment-bound robot data. But VLAs also try to inherit VLM knowledge (e.g. RT-2); what matters is whether it survives training.
    2. Composing existing skills — a new task becomes a new combination of reliable skills. Bounded by the skill library: a correct plan cannot open a bottle without a bottle-opening skill.
    3. Runtime mechanisms, not the model — keeping history, checking real outcomes, replanning. These can be added around a VLA too. Explaining a failure is not the same as detecting one; checks must rest on environment feedback.
    4. Versus WAM — task-level reasoning may be enough when the question is ordering ("clear the cups or wipe the table first?"); predicting future states helps more with contact, sliding, and novel motions, at extra compute and compounding prediction error.

    What a fair comparison must control: keep the same executor and add VLM planning, memory, and outcome checks one at a time; test new instruction combinations, new objects, new physical motions, and interruptions; do not compare success rates across different real-robot setups.

    Surveys to cite (verify before adding to References): Towards Embodied Agentic AI (2025); Agentic LLM-based robotic systems … agenticness and ethics (Frontiers in Robotics and AI, 2025); Large VLM-based Vision-Language-Action Models for Robotic Manipulation: A Survey (2025, v3 2026); World Action Models: The Next Frontier in Embodied AI (May 2026); World-Action Models for Robot Learning and Control: A Survey (Sep 2026). */}

|  | VLM-driven agent | VLA | WAM |
|---|---|---|---|
| Question it answers | What to do next, and with which skill? | How should the robot move next? | What will happen if I act, and how do I reach the goal? |
| Input | Images, instruction, memory, tool results | Images, instruction, proprioception | Images, instruction |
| Output | Subtasks, skill calls, programs | Low-level action chunks | Predicted future (video or latent) and action chunks |
| Knowledge comes from | Web-scale vision-language pretraining, used directly | A VLM backbone, if it survives robot fine-tuning | Video and action data, learning physical dynamics |
| Memory and feedback | Keeps history, checks results, replans | Short observation window, no explicit check | Predicts outcomes, but does not check them |
| Strong at | Composing existing skills for new, long tasks | Smooth, dexterous, low-latency control | New scenes; contact and dynamics |
| Limited by | The skill library and its interfaces; reasoning latency | Scarce, embodiment-specific robot data | Compute cost and compounding prediction error |
